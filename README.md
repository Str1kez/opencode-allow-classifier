# opencode-allow-classifier

Плагин разрешений для OpenCode V2. Ставит на все shell-вызовы `ask`, а потом
понижает до `allow` те, которые считает безопасными: по allowlist, гардам и
классификатору. Опасные и необратимые команды остаются человеку.

Плагин видит только shell-вызовы с эффектом `ask`. `deny` он не трогает:
запрет выносится до хука и не пересматривается. `allow` тоже не его дело —
понижать нечего.

## Что делает

- Безопасные read-only команды внутри проекта перестают спрашивать: их
  отдаёт статический allowlist с гардами.
- Неизвестную команду оценивает модель вероятностью безопасности; выше
  порога — `allow`, ниже — `ask`.
- `sudo`, установка пакетов, `git push`, `rm` вне cwd и миграции уходят
  человеку всегда: это hard-ask, модель их не видит.
- Секреты, чтение вне cwd, запись и подстановки шелла оставляют `ask`:
  гард отменяет allowlist.
- Ошибка, таймаут или недоступная модель оставляют `ask`. Плагин никогда не
  превращает вызов в `allow` ценой безопасности.

## Требования и совместимость

- Проверено на OpenCode 2.2.4 (standalone) с API плагинов 2.2.x. Другие версии
  не проверялись: если хост не отдаёт `permission.hook("evaluate")` и
  `experimental.generate.decisions`, плагин работать не будет.
- Исходники на TypeScript загружаются напрямую: `exports` в `package.json`
  указывают на `./src/index.ts`, `./src/tui.ts` и `./src/rpc.ts`. Шага сборки
  нет, `dist/` не появляется, править `src/` можно без пересборки.
- Пакет не опубликован (`private`, версия `0.0.0`), поэтому ставится
  локальным путём.
- Тесты и смоуки гоняются на Node 26 в контейнере
  [sandbox/](sandbox/README.md).

## Установка

Правила в `permissions` применяются по порядку, побеждает **последнее**
совпавшее. Поэтому catch-all `ask` стоит первым, deny — после него.

1. Поставь catch-all `{ "action": "shell", "resource": "*", "effect": "ask" }`.
   Без него плагин не увидит команду: он обрабатывает только `ask`.
2. Поставь deny-правила после catch-all. Тогда запрет выносится до плагина,
   и классификатор не может его отменить.
3. Подключи плагин объектом и передай `options`.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    // Catch-all: всё, что не поймано ниже, уходит на подтверждение.
    { "action": "shell", "resource": "*", "effect": "ask" },

    // Запреты после catch-all: хук для них не вызывается.
    { "action": "shell", "resource": "git push --force*", "effect": "deny" },
    { "action": "shell", "resource": "git push -f*", "effect": "deny" },
    { "action": "shell", "resource": "git reset --hard*", "effect": "deny" },
    { "action": "shell", "resource": "rm -rf*", "effect": "deny" },
    { "action": "shell", "resource": "*--no-verify*", "effect": "deny" },
    { "action": "shell", "resource": "*--dangerously-skip-permissions*", "effect": "deny" }
  ],
  "plugins": [
    {
      // Путь к корню пакета, где лежит package.json с exports.
      // Не src/index.ts.
      "package": "/абсолютный/путь/к/opencode-allow-classifier",
      "options": {
        "enabled": true,
        "threshold": 0.9,
        "timeout_ms": 3000,
        "include_system_context": false
      }
    }
  ]
}
```

Плагин подключается объектом: только так `options` доходят до `ctx.options`.
Строковая запись не даёт задать опции, и все значения останутся дефолтными.
`package` указывает на каталог с `package.json`, а не на `src/index.ts`: хост
читает `exports`, а не конкретный файл.

После правки конфига перезапусти OpenCode. Опции читаются при старте
серверной части, там же регистрируются хук и RPC. Выбор модели в TUI, если
его не перекрывает опция `model`, применяется со следующего вызова без
рестарта.

Как проверить, что плагин поднялся:

- `ls` выполняется без подтверждения и появляется в аудите как
  `allow`/`allowlist`;
- `sudo -n true` спрашивает и пишется в аудит как `ask`/`hard-ask`;
- в TUI есть команда `/classifier`.

## Опции

| Опция | Тип | По умолчанию | Поведение |
|---|---|---|---|
| `enabled` | boolean | `true` | Kill switch. Выключает только литеральный `false`: плагин не регистрирует хук, RPC и `/classifier`. |
| `model` | string | не задана | Модель классификатора вида `provider/model`. Без опции работает порядок: оверрайд из `/classifier` → `opencode/jev-1.13-free`. Должна быть decision-моделью. |
| `threshold` | number | `0.9` | Порог вероятности в `(0, 1]`. `probability >= threshold` даёт `allow`, иначе `ask`. |
| `timeout_ms` | integer | `3000` | Общий бюджет вызовов модели в миллисекундах, от 1 до 60000. Включает повторную попытку. |
| `include_system_context` | boolean | `false` | Отправлять последнее system-сообщение сессии в промпт. Включает только литеральный `true`. |
| `audit_dir` | string | state-каталог OpenCode | Куда писать `evaluate-YYYY-MM.jsonl`. По умолчанию `$XDG_STATE_HOME/opencode`, иначе `~/.local/state/opencode`. |

Невалидное значение не ломает плагин: оно игнорируется, применяется дефолт.
Считается невалидным:

- `model` — не строка вида `provider/model`: пустая половина, пробелы,
  длина больше 200 символов;
- `threshold` — не число, `NaN`/бесконечность, `<= 0` или `> 1`;
- `timeout_ms` — не целое, `<= 0` или `> 60000`;
- `audit_dir` — пустая строка или не строка.

`enabled` и `include_system_context` читаются строго: `"false"` строкой или
`1` не выключают и не включают ничего.

`model` должна отвечать на операцию `decisions`. Чат-модель этого не умеет,
поэтому каждый вызов останется `ask` — сверяй поле `model` в аудите.

## Как принимается решение

1. **Фильтр хука.** Плагин получает только `action: "shell"` с эффектом
   `ask`. Остальные действия, `allow` и `deny` не классифицируются и в аудит
   не попадают.
2. **Hard-ask.** Сразу `ask`, модель не вызывается: `sudo`/`doas`/`sudoedit`;
   установка пакетов (`npm`/`pnpm`/`yarn`/`pip`/`uv`/`cargo`/`brew`, включая
   `npm ci`, голые `yarn`/`pnpm`, `python -m pip install`, `uv sync`,
   `cargo install`, `brew upgrade`); `git push`; `rm` с путём вне cwd;
   миграции (`alembic upgrade`, `prisma migrate`, `goose`, `flyway`).
   Программа ищется за env-префиксами (`FOO=1`), обёртками (`env`, `nohup`,
   `command`, `time`), ведущим обратным слэшем и глобальными флагами git
   (`git -C /tmp push`).
3. **Allowlist с гардами.** `allow` без модели для read-only команд внутри
   cwd: `ls`, `pwd`, `cat`, `head`, `tail`, `wc`, `file`, `stat`, `du`,
   `df`, `which`, `echo`, `date`, `whoami`, `uname`, `rg`, `grep`, `jq`,
   `find`, `git status`, `git diff`, `git log`, `git show`, `git branch`
   (только листинговые флаги), `git remote -v`, `git rev-parse`, `git blame`,
   `git stash list`. Гард отменяет allowlist и оставляет `ask`:
   - секреты (`.env`, `.ssh`, `id_rsa`, `credentials`, `*.pem`, `*.key`,
     `.git/`, history-файлы, `~/.config/opencode`, `~/.local/share/opencode`
     и остальные из [docs/permissions.md](docs/permissions.md));
   - чтение вне cwd, симлинк наружу, программа по недоверенному пути
     (`./cat`, `/tmp/evil/git`);
   - рекурсивный поиск, который читает файлы, не названные в argv
     (`rg -u`/`--hidden`/`--no-ignore*`, `grep -r` с корнем в cwd);
   - запись: `>`/`>>`, `tee`, `-o` у git, `--output`;
   - исполнение чужих программ: `rg --pre`, `git --ext-diff`/`--textconv`;
   - флаги чтения файла в обход позиционного аргумента (`--contents`,
     `--slurpfile`, `--rawfile`, `--from-file`, `jq -f`);
   - команды, меняющие состояние под видом чтения (`date -s`, `tail -f`);
   - бесконечное чтение (`/dev/urandom`, `/dev/zero`, `cat -`);
   - управляющие байты и шелл-метасимволы (`;`, `&`, `|`, `$`, скобки,
     глобы, обратный слэш, перевод строки).
4. **Кэш.** In-memory, TTL 30 минут, до 500 записей. Ключ — cwd, команды
   события и хеш system-контекста, если опция включена. Повтор не вызывает
   модель, одинаковые параллельные вызовы делят один запрос, ошибки не
   кэшируются. Перед кэшем плагин одним запросом читает сессию: последнюю
   реплику пользователя и system-сообщение, таймаут 1,5 с. Ошибка чтения
   деградирует до классификации без них.
5. **Классификатор.** `allow`, если вероятность безопасности
   `>= threshold`, иначе `ask`. Модель резолвится так: `model` из конфига →
   оверрайд из `/classifier` → `opencode/jev-1.13-free`. При ошибке
   провайдера — одна повторная попытка с `opencode/jev-1.13`. Таймаут,
   `Generate.ErrorAnswer` и неожиданный ответ не повторяются. `timeout_ms` —
   общий бюджет на все попытки: повторная получает остаток времени.
6. **Fail-open `ask`.** Ошибка или таймаут классификатора оставляют `ask` с
   источником `error` в аудите. Пустой набор ресурсов и недоступный
   классификатор тоже дают `ask`: понизить вызов без вердикта нельзя.

Компаунд (`&&`, `|`) оценивается целиком: одна небезопасная часть оставляет
`ask` всему вызову. Неизвестные части уходят в модель одним запросом, и
рубрика требует оценивать вызов по самой опасной команде.

## System-контекст и приватность

По умолчанию system-сообщение сессии в модель не уходит: это текст проекта
или агента, он может содержать внутренние данные, а классификатор может
работать на внешнем провайдере.

`include_system_context: true` — осознанное согласие. Последнее
system-сообщение (до 2000 символов вместе с маркером `[truncated]`)
добавляется в недоверенный блок промпта. В аудит попадают только хеш, длина
и флаг использования, не текст. Хеш входит в ключ кэша, поэтому смена
инструкций не переиспользует старый вердикт. Риски и альтернативы —
в [ADR-0003](docs/adr/0003-system-context-in-classifier.md).

## `/classifier` в TUI

Команда открывает пикер decision-моделей: текущая модель подсвечена, Jev идёт
категорией `System One`, остальные — по провайдеру, выключенные скрыты,
дубликаты схлопываются. Чат-модели не предлагаются: они не умеют отвечать на
`decisions`.

Выбор сохраняется в серверном `ctx.storage` под ключом `model_override`,
поэтому переживает рестарт TUI и сервера. Модель промпта TUI при этом не
меняется. Опция `model` в конфиге побеждает: выбор сохранится, но тост
предупредит, что эффективная модель не изменилась. Успешный выбор очищает
кэш вердиктов.

Пикер есть только в TUI. RPC-методы `config` и `setModel` регистрирует
серверная часть, поэтому headless-запуск видит сохранённый оверрайд, даже
когда пикера нет. Детали контракта — в [docs/permissions.md](docs/permissions.md).

## Аудит

Каждое классифицированное решение пишется строкой JSON в
`$XDG_STATE_HOME/opencode/evaluate-YYYY-MM.jsonl` (по умолчанию
`~/.local/state/opencode/`), файл на месяц. Каталог переопределяется опцией
`audit_dir`.

Поля: `time`, `session`, `agent`, `cwd`, `resources`, `rule`, `verdict`,
`source`, `probability`, `model`, `latency`, `task`, `systemContext`
(`used`, `length`, `hash`). Источники: `hard-ask`, `allowlist`, `model`,
`cache`, `error` и `default` для пустого набора ресурсов.

Текст system-сообщения в файл не пишется никогда — только хеш и длина.
Ошибка записи не влияет на вердикт: каталог может быть только для чтения,
решение всё равно будет вынесено.

## Диагностика

### Плагин не загрузился

`package` указывает на `src/index.ts` вместо корня пакета, версия API не
2.2.x или в опциях стоит `enabled: false`. Проверь, что путь ведёт к каталогу
с `package.json`, и перезапусти OpenCode.

### `ls` всё равно спрашивает

- Плагин не активен: см. предыдущий пункт.
- `enabled: false` — catch-all остаётся, понижать некому.
- Сработал гард: путь вне cwd, секрет в аргументах, редирект (`ls > out`).
  В аудите будет `ask` с `source: allowlist` и `rule: guard:*`.
- Нет catch-all `ask`: плагин вообще не получает вызов, потому что хуку
  нечего понижать. Если при этом команду ловит другое `ask`-правило, она
  спрашивает мимо плагина.

### Порядок правил сломан

Если deny стоит до catch-all, побеждает последнее совпавшее правило — `ask`.
Запрет перестаёт работать, а команда приходит в плагин, который может её
понизить. Deny должен идти после catch-all.

### Классификатор всегда оставляет `ask`

Смотри аудит:

- `probability` ниже `threshold` — так и задумано, можно снизить порог;
- `source: error`, `rule: classifier:provider` — ошибка провайдера, проверь
  креды и доступность модели;
- `source: error`, `rule: classifier:timeout` — не хватило `timeout_ms`.
  Бюджет общий на обе попытки; чтение сессии ограничено отдельными 1,5 с и
  опцией не меняется;
- `model` в аудите — чат-модель: выбери decision-модель через `/classifier`
  или опцией `model`.

### Нет файла аудита

- `enabled: false` — плагин не работает.
- Не было ни одного вызова с эффектом `ask`: файл создаётся при первом
  решении, пустой лог не появляется.
- `audit_dir` указывает не туда.
- Каталог не пишется: ошибка записи глотается, вердикт при этом не меняется.

### В TUI нет `/classifier`

Команда регистрируется только в TUI и только при включённом плагине. После
смены `enabled` нужен рестарт TUI. В headless-режиме пикера нет: доступны
только RPC-методы `config` и `setModel`.

### В аудите непонятные или повторяющиеся записи

`source` говорит, кто вынес решение: `hard-ask`, `allowlist`, `model`,
`cache`, `error` или `default`. `model` и `cache` — один и тот же
классификатор, разница только в том, вызывалась ли модель. Повторы одной
команды — это отдельные вызовы агента, а не дубликаты лога.

## Смоук-чеклист

Приёмочный список. Отмечай по факту прогона, а не по ожиданию.

- [ ] `ls` проходит без подтверждения, аудит пишет `allow`/`allowlist`.
- [ ] `sudo -n true` остаётся `ask` с `source: hard-ask`, модель не
      вызывается.
- [ ] Команда вне allowlist, безопасная по контексту (например,
      `sed -n '1,20p' README.md`), получает `allow` с `source: model`.
- [ ] Опасная команда внутри cwd (например, `rm build/old.log`) остаётся
      `ask` с `source: model`.
- [ ] Повтор той же команды в том же cwd даёт `source: cache` и не вызывает
      модель.
- [ ] `/classifier` открывается, выбор модели переживает рестарт TUI и
      сервера.
- [ ] `enabled: false` плюс рестарт: `ls` снова спрашивает, `/classifier`
      пропадает из автодополнения.

Прогон в контейнере — [sandbox/README.md](sandbox/README.md).
