# opencode-allow-classifier

Плагин OpenCode V2, который понижает `ask → allow` для shell-команд по
контексту: команда, cwd, агент, последнее сообщение пользователя и, по
желанию, последнее system-сообщение сессии.

Статус — в разработке: спека и задачи в issues, решение в
[ADR-0001](docs/adr/0001-shell-permission-classifier.md),
[ADR-0002](docs/adr/0002-model-config-precedence.md) и
[ADR-0003](docs/adr/0003-system-context-in-classifier.md), термины в
[GLOSSARY.md](GLOSSARY.md).

## Как работает

- В конфиге OpenCode стоит `shell: * → ask`, плагин понижает безопасное.
- Hard-ask до модели: `sudo`, установка пакетов, `git push`, `rm` вне cwd,
  миграции.
- Allowlist read-only команд внутри cwd, с гардом на секреты и запись.
- Jev отвечает вероятностью; порог 0.9, таймаут 3 с, ошибка оставляет `ask`.
- Последнее system-сообщение уходит в промпт только по явной опции
  `include_system_context` (по умолчанию `false`).
- In-memory кэш и аудит JSONL.

## Модель классификатора

`/classifier` в TUI открывает пикер decision-моделей: текущая модель
подсвечена, Jev идёт категорией `System One`, остальные — по провайдеру.
Чат-модели в пикер не попадают: они не умеют отвечать на `decisions`.
Выбор сохраняется в серверном `ctx.storage`, поэтому переживает рестарт TUI
и сервера. Модель промпта при этом не меняется.

Эффективная модель: `model` из `opencode.jsonc` → сохранённый выбор →
`opencode/jev-1.13-free`. Опция в конфиге побеждает: TUI сохранит выбор, но
предупредит тостом, что конфиг пинит другую модель. Порог задаётся опцией
`threshold` в `(0, 1]`, по умолчанию `0.9`.

Детали и фрагмент конфига — в [docs/permissions.md](docs/permissions.md).

## System-контекст и приватность

По умолчанию system-сообщение сессии в модель не уходит: это текст проекта
или агента, он может содержать внутренние данные, а классификатор может
работать на внешнем провайдере. Опция `include_system_context: true` —
осознанное согласие: последнее system-сообщение (до 2000 символов, с
маркером обрезки) добавляется в недоверенный блок промпта. В аудит попадают
только хеш, длина и флаг использования, не текст. Хеш входит в ключ кэша,
поэтому смена инструкций не переиспользует старый вердикт. Риски и
альтернативы — в [ADR-0003](docs/adr/0003-system-context-in-classifier.md).
