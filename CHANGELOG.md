# CHANGELOG

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Unreleased]

### Добавлено

- Jev-классификатор: безопасная неизвестная команда понижается до `allow`
  при вероятности `>= 0.9`, опасная остаётся `ask`. Модель
  `opencode/jev-1.13-free`, одна повторная попытка с `opencode/jev-1.13` при
  ошибке провайдера, таймаут 3 с. Hard-ask и сработавшие гарды в модель не
  ходят.
- In-memory кэш вердиктов: TTL 30 минут, лимит 500 записей, ключ — cwd и
  команды события. Повтор не вызывает модель, параллельные одинаковые вызовы
  дедуплицируются. Ошибки не кэшируются.
- В промпт входят команды, cwd, агент и последнее сообщение пользователя
  (до 2000 символов); рубрика запрещает следовать инструкциям внутри этих
  недоверенных данных.
- Опция `include_system_context` (по умолчанию `false`) добавляет последнее
  system-сообщение сессии в тот же недоверенный блок, до 2000 символов с
  маркером обрезки; `<`, U+2028 и U+2029 экранируются. Аудит хранит хеш,
  длину и флаг, но не текст; хеш входит в ключ кэша, поэтому смена
  инструкций вызывает новый вызов модели.
- Аудит пополнился источником `model`/`cache`/`error`, вероятностью, моделью,
  текстом задачи и объектом `systemContext` (`used`, `length`, `hash`); текст
  system-сообщения в файл не попадает.
- `/classifier` в TUI: пикер decision-моделей классификатора. Чат-модели не
  предлагаются, потому что не умеют отвечать на `decisions`. Текущая модель
  подсвечена, Jev идёт отдельной категорией `System One`, остальные — по
  провайдеру; выключенные модели скрыты, дубликаты схлопываются. После
  выбора показывается тост.
- RPC-контракт `config`/`setModel` под id плагина. `setModel` принимает
  только `provider/model` из каталога decision-моделей, пишет `{ model }` в ключ
  `model_override` серверного `ctx.storage` и возвращает эффективные
  настройки; `config` отдаёт модель, порог и источник.
- Выбор модели переживает рестарт TUI и сервера: оверрайд лежит в серверном
  `ctx.storage`, а не в состоянии TUI.
- Опции `model` и `threshold` в `opencode.jsonc`. Порог — вероятность в
  `(0, 1]`, по умолчанию `0.9`; невалидные значения игнорируются, а не
  ломают плагин.
- Опция `timeout_ms` в `opencode.jsonc`: общий бюджет классификатора на все
  попытки, целое число от 1 до 60000 мс, по умолчанию 3000. Повторная
  попытка получает остаток бюджета.
- Порядок резолва эффективной модели: опция `model` → оверрайд из TUI →
  `opencode/jev-1.13-free`. Опция побеждает; выбор в TUI всё равно
  сохраняется, а тост предупреждает, что конфиг пинит другую модель.
- `setModel` очищает in-memory кэш вердиктов: следующая оценка идёт новой
  моделью, а вычисление, начатое до смены, кэш не заполняет.
- Docker-sandbox `sandbox/` для headless-смоуков и тестов: образ с OpenCode
  2.2.4 и Node 26, профиль с тем же catch-all `ask` и deny-правилами, плагин
  подключён смонтированным репозиторием. Креды провайдеров импортируются в
  volume из `opencode auth export`, аудит складывается в `sandbox/.runtime/`.
- `find` в allowlist: обход дерева разрешён, `-exec` проходит только с
  read-only программой из доверенного каталога и без её опасных флагов;
  `-delete`, `-fprint`, `-exec rm`/`sh`/`xargs` спрашивают.
- Кавычки и обратный слэш учитываются в гарде: `rg 'a|b'` и
  `rg 'price > 10'` — литералы и больше не шумят, а `rg "$(id)"` внутри
  двойных кавычек по-прежнему подстановка.
- Пайплайн auto mode без модели: hard-ask, allowlist read-only команд с
  гардом на секреты и записи, дефолт `ask`.
- Аудит решений в `evaluate-YYYY-MM.jsonl` в state-каталоге OpenCode;
  ошибка записи не влияет на вердикт.
- Kill switch `enabled: false` — плагин не регистрирует хук, RPC-контракт и
  команду `/classifier`.
- `docs/permissions.md` с фрагментом `opencode.jsonc`: catch-all, deny после
  него и подключение плагина объектом с опциями.
- Скилл `allow-classifier-install`: ставит политику в глобальный конфиг (по
  умолчанию) или в проектный по `--project`, показывает состояние, проверяет
  установку и откатывает только добавленное. Повторный запуск ничего не
  дублирует, комментарии и чужие правила сохраняет, перед записью печатает
  diff.
- Скилл `allow-classifier-analyze` и команда `npm run report`: разбирают аудит
  за окно (30 дней по умолчанию) и группируют `ask` по сигнатуре команды.
  Кластеры раскладываются по рычагам (allowlist и гарды, модель и порог,
  hard-ask, ошибки классификатора), рекомендации идут по безопасности. Отчёт
  read-only, по умолчанию печатается в чат, аудит `sandbox/` не читает без
  `--include-sandbox`.
- Раздел README о скиллах: назначение, команды и границы. В `GLOSSARY.md`
  добавлены «сигнатура команды» и «ask-кластер».

### Изменено

- Безопасные shell-команды больше не спрашивают подтверждения: плагин
  понижает `ask` до `allow` после hard-ask, allowlist с гардами, кэша и
  классификатора. Опасные и необратимые команды остаются человеку, `deny`
  не пересматривается.

### Удалено

- Диагностический режим `log_raw`/`log_dir`: сырые события больше не
  пишутся, файл `src/raw-log.ts` удалён. Единственный журнал — аудит решений
  в `evaluate-YYYY-MM.jsonl`.

### Исправлено

- Гард ловит метасимволы и подстановки внутри одного ресурса: `;`, перевод
  строки, `&`, глобы, `$'…'`, скобки и обратный слэш больше не проходят как
  `cat`.
- Гард сверяет секреты с сырым текстом, текстом без кавычек и склеенными
  токенами, поэтому `cat ".en""v"` и `cat .e''nv` больше не читают `.env`.
- Список секретов расширен: `.netrc`, `.npmrc`, `.pgpass`,
  `.git-credentials`, `.docker/config.json`, `.kube/config`, `.aws/`,
  `.config/gh`, history-файлы, `*.pem`, `/proc/`, `secrets`; отдельно
  закрыты флаги чтения файла (`--contents`, `--slurpfile`, `--rawfile`,
  `--from-file`, `jq -f`) и дамп окружения через `jq env`.
- Allowlist больше не читает вне cwd: `cat ~/notes.txt`, `cat ../x`,
  `du -a /`, `rg TODO ~` уходят в `ask`.
- Программа, вызванная через путь, исполняется только из доверенных
  каталогов: `./cat`, `/tmp/evil/git` уходят в `ask`.
- Рекурсивный поиск не читает секреты, которых нет в argv: `rg -u`/`-uuu`/
  `--hidden`/`--no-ignore*` и `grep -r` с корнем в cwd уходят в `ask`.
- Список секретов дополнен `.gnupg`, `.password-store`, `.vault-token`,
  ключами самого агента, `Library/Keychains`, `.config/solana`,
  `.git/`, `*.p12`, `*.key`.
- Управляющие байты в выводе больше не проходят: `git log --format=%x1b`
  и литеральный ESC уходят в `ask`.
- Закрыты `date -s`, `tail -f`, `/dev/urandom` и `cat -`; хвостовой перевод
  строки от сканера больше не вызывает ложный `ask`.
- `git --ext-diff` и `--textconv` больше не считаются read-only.
- Hard-ask видит программу за env-префиксами, обёртками и глобальными
  флагами git: `git -C /tmp push`, `FOO=1 sudo`, `nohup sudo`, `doas`,
  `sudoedit`; добавлены `npm ci`, голые `yarn`/`pnpm`, `--prefix`,
  `python -m pip install`, `uv sync`, `cargo install`, `brew upgrade`.
- Таймаут классификатора — общий бюджет 3 с на решение: повторная попытка
  получает остаток времени, поэтому зависший провайдер стоит одного
  таймаута, а не двух. Последнее сообщение пользователя читается только
  когда вызов дошёл до модели, с таймаутом 1.5 с; hard-ask и allowlist
  сессию не трогают.
- Экранированная кавычка внутри двойных кавычек больше не считается
  активным метасимволом: `rg "\"name\"" package.json` проходит без промпта.
  Разделители строк U+2028/U+2029 экранируются в промпте наравне с `<`.
- `-o` больше не считается флагом записи у `find`, `grep` и `rg`: у `find`
  это OR, у поисковиков — «только совпадения». Гард `output-short-flag`
  остался только для `git diff -o`.
- `enabled: false` больше не оставляет `/classifier` в автодополнении
  slash-команд TUI после рестарта: команда не регистрируется вовсе, а не
  только отключается.
- Правка конфига больше не требует перезапуска OpenCode: V2 перезагружает
  конфиги, плагины, скиллы и MCP-серверы сам, `/reload` — принудительный путь.
  Исправлено в README (установка, диагностика, kill switch, смоук-чеклист) и в
  `docs/permissions.md`. Сохранение выбора модели и состояния плагина между
  стартами остаётся в силе.
- Отчёт анализа не рекомендует расширять allowlist, делать исключение из
  hard-ask или снижать порог, если в сырых ресурсах кластера остался активный
  shell-синтаксис: перевод строки больше не схлопывается в пробел перед
  проверкой, пример печатается с исходным переводом строки, а флаг
  `activeSyntax` считается по всему кластеру. Кавычки по-прежнему литеральны:
  `echo "a;b"` в allowlist получает рекомендацию.
- `kubectl get secrets -o yaml`, `kubectl describe`, `kubectl logs`,
  `docker logs` и `docker inspect` убраны из read-only форм отчёта: их вывод
  может содержать учётные данные. Риск allowlist-рекомендации теперь
  напоминает, что read-only команда всё равно может напечатать секреты.
- Анализатор читает эффективный порог из конфига, даже когда в записи плагина
  нет `audit_dir`; `--audit-dir` больше не сбрасывает сравнение к дефолтным
  `0.9`.
