# Политика разрешений shell

Единственное место, где живёт политика. В репозитории плагина — только этот
документ; правки конфига делаются в dotfiles и повторяют фрагмент ниже.

## Принцип

`shell: * → ask` заменяет точечные ask-правила. Каждый shell-вызов сначала
требует подтверждения, а плагин понижает безопасные до `allow`. Deny-правила
стоят после catch-all: они выносятся до плагина, и хук для них не вызывается
вообще, поэтому классификатор не может отменить запрет.

Порядок правил важен: побеждает **последнее** совпавшее правило.

## `opencode.jsonc`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    // Catch-all: всё, что не поймано ниже, уходит на подтверждение.
    { "action": "shell", "resource": "*", "effect": "ask" },

    // Запреты стоят после catch-all и не пересматриваются плагином.
    { "action": "shell", "resource": "git push --force*", "effect": "deny" },
    { "action": "shell", "resource": "git push -f*", "effect": "deny" },
    { "action": "shell", "resource": "git reset --hard*", "effect": "deny" },
    { "action": "shell", "resource": "rm -rf*", "effect": "deny" },
    { "action": "shell", "resource": "*--no-verify*", "effect": "deny" },
    { "action": "shell", "resource": "*--dangerously-skip-permissions*", "effect": "deny" }
  ],
  "plugins": [
    {
      "package": "@str1kez/opencode-allow-classifier",
      "options": {
        "enabled": true,
        // Модель классификатора; без опции — выбор из /classifier, затем дефолт.
        // "model": "opencode/jev-1.13-free",
        // Вероятность в (0, 1]; ниже — больше автоматических allow.
        "threshold": 0.9,
        // Общий бюджет вызовов модели: целое число миллисекунд от 1 до 60000.
        "timeout_ms": 3000,
        // System-сообщение может содержать внутренние данные; по умолчанию не уходит.
        "include_system_context": false,
        // Каталог аудита; по умолчанию state-каталог OpenCode.
        // "audit_dir": "/var/log/opencode-classifier"
      }
    }
  ]
}
```

Плагин подключается объектом с `options`, иначе `ctx.options` пустой. Пока
пакет не опубликован, в `package` указывается путь к каталогу пакета — тому,
где лежит `package.json` с `exports`, а не к `src/index.ts`. В sandbox это
`"package": "/home/node/repo"`.

Опции, которые читает плагин:

- `enabled` — по умолчанию `true`; выключает только литеральный `false`;
- `model` — строка `provider/model`; без неё работает порядок резолва из
  раздела «Модель, порог и таймаут»;
- `threshold` — вероятность в `(0, 1]`, по умолчанию `0.9`;
- `timeout_ms` — целое число миллисекунд от 1 до 60000, по умолчанию `3000`;
  общий бюджет вызовов модели, включая повторную попытку;
- `include_system_context` — по умолчанию `false`; включает только
  литеральный `true`;
- `audit_dir` — непустая строка; по умолчанию state-каталог OpenCode.

Невалидное значение игнорируется и не ломает плагин: `model` не вида
`provider/model`, `threshold` вне `(0, 1]`, `timeout_ms` не целое или вне
диапазона, пустой или нестроковый `audit_dir`.

## Что делает плагин

1. **Hard-ask** — вердикт `ask`, модель не вызывается: `sudo`/`doas`/
   `sudoedit`, установка пакетов (`npm`/`pnpm`/`yarn`/`pip`/`uv`/`cargo`/
   `brew`, включая `npm ci`, голые `yarn`/`pnpm`, `python -m pip install`,
   `uv sync`, `cargo install`, `brew upgrade`), `git push`, `rm` с путём вне
   cwd, миграции (`alembic upgrade`, `prisma migrate`, `goose`, `flyway`).
   Программа ищется за env-префиксами (`FOO=1`, `env`, `nohup`, `command`,
   `time`, `\`), а у git пропускаются глобальные флаги (`-C`, `-c`,
   `--no-pager`, `--git-dir`). Поэтому `git -C /tmp push` и `FOO=1 sudo`
   остаются hard-ask.
2. **Allowlist с гардом** — `allow` без модели: `ls`, `pwd`, `cat`, `head`,
   `tail`, `wc`, `cut`, `tr`, `nl`, `strings`, `printf`, `true`, `sleep`,
   `sort` без `-o`/`--output` и без `--compress-program` (`sort -T .` пишет
   временные файлы внутри cwd и удаляет их сам), `file`, `stat`, `du`, `df`,
   `which`, `echo`, `date`, `whoami`, `uname`, `rg`, `grep`, `jq`, `find`,
   `sed -n 'Np'` и `sed -n 'N,Mp'`
   (только диапазон печати: `-i`, `-e`, `w`, `s///` и шаг `1~2p` уходят
   к классификатору),
   `gh --version` и `gh` с группами `issue`, `pr`, `repo`, `run`, `release`,
   `workflow` и глаголами `view`/`list` (только они: `gh api`, `gh auth`,
   `gh issue close` и `gh pr merge` уходят к классификатору),
   `git status`, `git diff`, `git log`, `git show`, `git branch` (только
   листинговые флаги), `git remote -v`, `git remote get-url`,
   `git rev-parse`, `git blame`, `git stash list`, `git worktree list`,
   `git merge-base`, `git ls-files`, `git rev-list`, `git for-each-ref`,
   `git config --get`, `git describe`, `git shortlog`. `awk`, `env` и `cd`
   в allowlist не входят: `awk` и `env` исполняют чужой код, а `cd`
   рассинхронизирует проверку путей с реальным каталогом.
   У git глобальные флаги (`-C`, `--no-pager`, `--git-dir`) не мешают
   сопоставлению с allowlist: `git -C ./sub log` разрешён. Путь из `-C`,
   `--git-dir` и `--work-tree` проверяет гард `outside-cwd`, поэтому
   `git -C /tmp log` спрашивает. `git -c`, `--config-env` и `--exec-path=`
   тоже пропускаются к allowlist, но их отменяет гард
   `git-command-override`: значение конфига может называть программу
   (`core.pager`, `diff.external`, `alias.*`), а `--exec-path=` указывает,
   откуда брать исполняемую подкоманду. Такая команда read-only не является.
   `find` разрешён только как обход: `-exec` проходит, если запускает
   read-only программу (`cat`, `grep`, `rg`, `wc` и т. п.) из доверенного
   каталога и без собственных опасных флагов; `-delete`, `-fprint`, `-fprintf`,
   `-execdir`, `-ok` и `-exec rm`/`sh`/`xargs` спрашивают.
   Allowlist действует только на доказуемо read-only чтение **внутри cwd**.
   Позиционный аргумент-путь (содержит `/`, начинается с `~`, равен `.` или
   `..`) резолвится лексически с разворотом `~` и `..`; путь вне рабочего
   каталога уходит в `ask`. `rg`/`grep` без пути по умолчанию ищут в cwd —
   это разрешено. Программа, вызванная через путь (`./cat`,
   `/tmp/evil/git`), разрешается только из доверенных каталогов `/bin`,
   `/usr/bin`, `/usr/local/bin`, `/opt/homebrew/bin`, `/opt/homebrew/sbin`,
   `/usr/sbin`, `/sbin`. Голое имя без `/` считается системным: PATH не
   резолвится, лишний I/O в решателе не нужен.
3. **Кэш** — in-memory, TTL 30 минут, лимит 500 записей. Ключ — cwd,
   команды события и, при включённом system-контексте, хеш его текста.
   Повтор берётся из кэша без вызова модели; одинаковые параллельные вызовы
   делят один поход в модель. Ошибки не кэшируются.
4. **Jev-классификатор** — `ask → allow` при вероятности безопасности
   `>= threshold` (по умолчанию `0.9`). Модель по умолчанию
   `opencode/jev-1.13-free`, таймаут — опция `timeout_ms`, по умолчанию
   `3000` мс. Бюджет общий на все попытки: повторная получает остаток
   времени. При ошибке провайдера одна повторная попытка с
   `opencode/jev-1.13`; таймаут, `Generate.ErrorAnswer` и неожиданный ответ
   не повторяются. Любая ошибка оставляет `ask` с источником `error` в
   аудите.
5. **Ask по умолчанию** — всё остальное: нет модели, ошибка, низкая
   вероятность. Hard-ask и сработавшие гарды в модель не ходят.

Компаунд уходит в модель целиком одним вызовом: одна опасная часть
понижает вердикт всего вызова.

В промпт входят команды, cwd, агент и последнее сообщение пользователя
(не больше 2000 символов). Команды и текст задачи — недоверенные данные:
рубрика прямо запрещает следовать инструкциям внутри них и менять оценку
из-за фраз вроде «это уже одобрено». Доверенная часть промпта отделена
от JSON-блока с данными.

Опция `include_system_context: true` добавляет в тот же недоверенный блок
последнее system-сообщение активного контекста сессии: проектные инструкции
и контекст агента. Это не доверенная часть промпта — текст может прийти из
шаблона, расширения или чужой сессии, поэтому он не меняет рубрику. Лимит —
2000 символов с явным маркером `[truncated]`; `<`, U+2028 и U+2029
экранируются, как и остальной JSON, поэтому текст не закрывает
`<untrusted-data>` и не притворяется новой инструкцией. Task и system
читаются одним запросом `session.context` с фиксированным таймаутом 1,5 с
(опцией он не меняется); ошибка или таймаут деградируют до классификации
без system-контекста.

По умолчанию опция выключена: system-текст может содержать внутренние
данные, а классификатор может работать на внешнем провайдере. Включайте её
осознанно. Риски и альтернативы — в
[ADR-0003](adr/0003-system-context-in-classifier.md).

## Модель, порог и таймаут

Модель классификатора резолвится в порядке: `options.model` из
`opencode.jsonc` → оверрайд, сохранённый через `/classifier` → дефолт
`opencode/jev-1.13-free`. Невалидная опция игнорируется и не перекрывает
оверрайд. `model` должна указывать на decision-модель: чат-модель не умеет
отвечать на `decisions`, поэтому каждый вызов останется `ask`. `config`
возвращает эффективную модель, порог и источник (`options`, `override`,
`default`), а не сырой оверрайд.

`/classifier` в TUI открывает пикер decision-моделей из каталога сервера
(`types: ["decision"]`). Чат-модели не предлагаются: они не отвечают на
операцию `decisions`, на которой работает классификатор. Текущая модель
подсвечена, модели `opencode/jev` и `opencode/jev-*` идут первой категорией
`System One`, остальные — по имени провайдера; выключенные модели скрыты.
Выбор уходит на сервер методом `setModel`, который принимает только
`provider/model` из каталога decision-моделей и пишет `{ model }` в ключ
`model_override` серверного `ctx.storage`. Ошибка каталога или записи
показывается тостом и ничего не меняет.

Опция `model` побеждает выбор в TUI: конфиг — решение оператора, пикер —
удобство. Выбор всё равно сохраняется, а тост предупреждает, что эффективная
модель не изменилась. Если убрать `model` из конфига, вернётся последний
выбор из TUI, а не дефолт. Порог задаётся опцией `threshold` в `(0, 1]`,
по умолчанию `0.9`; невалидное значение игнорируется.

Таймаут задаётся опцией `timeout_ms`: целое число от 1 до 60000 мс, по
умолчанию `3000`. Это общий бюджет на вызовы модели, включая повторную
попытку с `opencode/jev-1.13`, поэтому зависший провайдер стоит одного
таймаута, а не двух. Чтение сессии в этот бюджет не входит: у него
фиксированный таймаут 1,5 с, опцией он не меняется.

Модель промпта TUI не трогает: плагин не вызывает `ui.model.variant.set`
и другие пишущие методы `ui.model`.
Оверрайд живёт в серверном `ctx.storage`, поэтому его видит и headless-запуск,
и следующий старт сервера. Успешный `setModel` очищает in-memory кэш
вердиктов: следующая оценка идёт новой моделью, а вычисление, начатое до
смены, кэш не заполняет.

Гард отменяет allowlist:

- секреты: `.env`, `.ssh`, `id_rsa`/`id_ed25519`/`id_ecdsa`, `credentials`,
  `*.pem`, `*.key`, `*.p12`, `.netrc`, `.npmrc`, `.yarnrc`, `.pgpass`,
  `.git-credentials`, `.git/` (креды в `.git/config`), `.docker/config.json`,
  `.kube/config`,
  `.aws/`, `.azure/`, `.config/gcloud`, `.config/gh`, `.config/solana`,
  `.config/opencode`, `.local/share/opencode`, `.gnupg`, `.password-store`,
  `.vault-token`, `Library/Keychains`, `.zsh_history`, `.bash_history`,
  `.gitconfig`, `/etc/`, `/proc/`, `secrets`, и `jq env` (дамп окружения);
- чтение вне cwd: любой позиционный аргумент-путь вне рабочего каталога —
  `cat ~/notes.txt`, `cat ../x`, `ls ../../..`, `du -a /`;
- недоверенная программа по пути: `./cat`, `/tmp/evil/git` — вердикт
  `guard:untrusted-binary`;
- рекурсивный поиск, который читает файлы, не названные в argv:
  `rg -u`/`-uuu`/`-a`/`--hidden`/`--no-ignore*`/`--binary`/`--follow`
  (`guard:rg-unrestricted`) и `grep -r`/`-R` с корнем в cwd
  (`guard:recursive-search`);
- запись: любой редирект `>`/`>>`, `tee`, `-o` у `git`, `--output`, а также
  `sort -o`/`sort --output` (`guard:sort-output`);
- подмена того, что запускает git: `git -c key=value`, `git --config-env=VAR key`
  и `git --exec-path=DIR` (`guard:git-command-override`) — конфиг может
  называть программу, а `--exec-path` меняет каталог подкоманд;
- исполнение чужих программ: `rg --pre`, `git --ext-diff`/`--textconv`,
  `sort --compress-program` (включая сокращённое `--compress-p`) — sort
  запускает указанную программу на временных файлах;
- чтение файла в обход позиционного аргумента: `--contents`, `--slurpfile`,
  `--rawfile`, `--from-file`, `jq -f` (jq-программа может напечатать `env`);
- команды, которые меняют состояние, притворяясь чтением: `date -s`/
  `--set`, `tail -f`/`-F`/`--follow`;
- вечное или блокирующее чтение: `/dev/urandom`, `/dev/random`, `/dev/zero`,
  `/dev/stdin`, `/dev/fd/`, `cat -`;
- управляющие байты: git-формат `%x` и литеральный ESC (OSC 52 — клипборд,
  CSI — подмена экрана);
- шелл-синтаксис внутри ресурса: операторы, подстановки и любые
  метасимволы ``; \n & | ` $ ( ) { } < > \ ! * ? [ ]``.

Гард смотрит на сырой текст, на текст без кавычек (`cat ".en""v"` — это
`cat .env`) и на склеенные токены. Метасимволы проверяются по сырому
ресурсу: токенизатор приклеивает `;` к предыдущему слову, и без этого
`cat x;git push --force` проходил бы как `cat`. Хвостовые пробельные
символы и переводы строк перед этой проверкой срезаются: сканер иногда
отдаёт ресурс с `\n` на конце, и `cat a\n` не должен спрашивать. Внутренний
перевод строки по-прежнему `ask`.

Компаунд (`&&`, `|`) оценивается целиком: если хотя бы один ресурс не прошёл,
весь вызов решается как одно целое — гард оставляет `ask`, а неизвестные части
уходят в модель одним запросом.

## Границы allowlist и остаточный риск

Гард по путям сравнивает резолвленные пути, а не строковые префиксы, и
смотрит через симлинки: плагин на границе решает `realpath` для cwd и для
пути из argv, поэтому `notes -> ~/.ssh/id_rsa` спрашивает. Отсутствующий
путь резолва не получает и проверяется лексически.

Рекурсивный поиск закрыт не полностью:

- `rg` без флагов пропускает скрытые файлы и уважает ignore-файлы, поэтому
  `.env` он не читает. Но не скрытый и не проигнорированный файл с секретом
  (`server.key`, `credentials.json`) `rg TODO` всё равно просканирует —
  гард по подстроке срабатывает только когда путь назван в argv;
- `grep -r` с корнем в cwd спрашивает, но `grep -rn TODO src` разрешён:
  внутри `src` может лежать свой `.env` или ключ. Мы ограничиваем корень
  поиска, а не содержимое дерева;
- `find -exec grep` разрешён, но это тот же обход дерева: гард видит только
  имя программы и её флаги, а не то, какие файлы она в итоге прочитает.

Доверенные каталоги — данные политики, а не проверка подписи: подмена
бинарника в `/usr/bin` или шим раньше в `PATH` (для голого имени) вне
модели угроз плагина.

Гард осознанно шумный: `date +%x`, `grep -r . .` и глобы в незакавыченном
виде (`cat .e*`) спрашивают. Кавычки и обратный слэш учитываются: `rg 'a|b'`
и `rg 'price > 10'` — литералы, а `rg "$(id)"` внутри двойных кавычек
по-прежнему подстановка. Ложный `ask` стоит одного нажатия, ложный `allow` —
исполнения команды. Сработавший гард в классификатор не уходит: эти случаи
остаются `ask`.

System-контекст — отдельный остаточный риск. Если включить
`include_system_context`, текст последнего system-сообщения уходит
выбранной модели, в том числе внешнему провайдеру. Плагин обрезает его до
2000 символов, экранирует разметку и не пишет в аудит, но не может
проверить, нет ли внутри внутренних данных или секретов. Это решение
оператора, поэтому дефолт — `false`.

## Изменения поведения

- `cat ~/notes.txt`, `cat ../x`, `ls ../../..`, `rg TODO ~` теперь
  спрашивают: allowlist больше не читает вне проекта.
- `./cat README.md` и `/tmp/evil/ls` спрашивают: локальный шим с именем
  read-only команды больше не исполняется молча.
- `rg -uuu -a . .`, `rg --hidden TODO`, `grep -r . .` спрашивают: рекурсия
  не читает секреты, которых нет в argv.
- `cat ~/.vault-token`, `cat ~/.gnupg/secring.gpg`,
  `cat ~/.local/share/opencode/auth.json`, `cat .git/config`,
  `cat server.key` спрашивают.
- `git log --format=%x1b`, `date -s`, `cat /dev/urandom`, `tail -f` спрашивают.
- `cat README.md\n` (хвостовой перевод строки от сканера) больше не
  спрашивает.
- `sed -n '1,120p' README.md`, `gh issue view 7`, `gh pr list`,
  `git worktree list`, `cut`, `tr`, `nl`, `strings`, `printf`, `true`,
  `sleep` и `sort` без `-o` больше не спрашивают.
- `git -C ./sub log` разрешён, `git -C /tmp log` спрашивает с
  `guard:outside-cwd`.
- `sort -o out.txt file` спрашивает с `guard:sort-output`;
  `sort --compress-program=./evil big.txt` — с
  `guard:sort-compress-program`; `git -c core.pager=cat log` — с
  `guard:git-command-override`.
- `git --exec-path=. log` спрашивает с `guard:git-command-override`, а
  `git --exec-path evil log` и `git --paginate log` уходят к классификатору:
  пробельная форма `--exec-path` не задаёт путь, а принудительный pager
  берёт программу из конфига.
- `cd /tmp` по-прежнему спрашивает: `cd` в allowlist не входит.

## Аудит

Каждое решение по shell-вызову пишется в
`$XDG_STATE_HOME/opencode/evaluate-YYYY-MM.jsonl` (по умолчанию
`~/.local/state/opencode/`), файл на месяц. Поля: время, session, agent, cwd,
resources, сработавшее правило, вердикт, источник (`hard-ask`, `allowlist`,
`model`, `cache`, `error`), вероятность, модель, латентность, текст задачи.
Для решений модели дополнительно видны вероятность и модель, для кэша —
сохранённые вероятность и модель. Объект `systemContext` содержит `used`,
`length` и `hash` (sha256); сам текст system-сообщения в аудит не пишется.
Ошибка записи не влияет на вердикт.
Каталог переопределяется опцией `audit_dir`; пустое или нестроковое значение
игнорируется, и остаётся state-каталог OpenCode.

## Скиллы

Политику можно собрать вручную по фрагменту выше или поставить скиллами
репозитория:

- `allow-classifier-install` — установка, `inspect`, `verify` и `rollback`.
  Из скиллов только он пишет конфиг: перед записью показывает diff, откат
  снимает ровно добавленное и только по явной просьбе.
- `allow-classifier-analyze` — разбор аудита: группирует `ask` по сигнатуре
  команды и раскладывает кластеры по рычагам. Только читает, политику не
  меняет.

Команды, флаги и границы — в
[.opencode/skills/README.md](../.opencode/skills/README.md).

## Kill switch

`"enabled": false` — плагин не регистрирует хук, RPC-контракт и команду
`/classifier`; после перезагрузки плагина она пропадает из автодополнения
slash-команд. V2 перезагружает плагин сам, `/reload` — принудительный путь.
Выключает только литеральный `false`: строка `"false"`, `0` или отсутствие
значения оставляют плагин включённым. Catch-all остаётся, поэтому `ls` снова
требует подтверждения. Это же поведение при сбое плагина: любая ошибка
оставляет `ask`, `deny` не пересматривается.
