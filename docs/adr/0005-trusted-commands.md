# `trusted_commands`: доверенные префиксы проекта

**Status**: accepted

Allowlist разрешает только доказуемо read-only формы. Свои проверки —
`npm test`, `npm run typecheck`, `node --test` — в него не входят и войти не
могут: `package.json` проекта исполняет произвольный код, и доказать
read-only нечем. За 60 дней аудита такие команды дали около 200 `ask`.

Глобальный конфиг для них — неверное место: у каждого проекта свои скрипты,
и разрешение, выданное одному репозиторию, не должно работать в другом.
Нужна опция уровня проекта, где оператор сам объявляет префиксы.

## Решение

Новая опция `trusted_commands` в `opencode.jsonc` — массив строк.

- Строка токенизируется и становится правилом-префиксом: точное совпадение
  токенов, без глобов и без пропуска глобальных флагов.
- Минимум два токена. Голый `npm` или `sh` доверяет любой подкоманде, а не
  одной команде.
- Запись с активным shell-синтаксисом (`;`, `&`, `|`, `$`, обратная кавычка,
  скобки, `<>`, `!`, глобы `* ? [ ]`, перевод строки) отбрасывается: префикс
  должен совпадать с набранной командой, а не с результатом раскрытия. CR,
  NBSP и другие пробельные символы, кроме пробела и таба, тоже запрещены:
  токенизатор делит по ним слово. Кавычки только группируют токены. Обратный
  слэш запрещён: токенизатор его не разворачивает, поэтому запись не совпадала
  бы с исполняемой командой.
- Невалидная запись отбрасывается молча, как битый `threshold`; не массив —
  пустой список. Ошибка конфига не должна выключать плагин.
- Принимается не больше 50 записей: читаются первые 50, остальные игнорируются,
  даже если валидны. Битая запись внутри окна просто выпадает.

Правило применяется внутри allowlist-шага, после встроенной таблицы:
совпадение даёт `allow` с `source: allowlist` и `rule: trust`. Встроенные
read-only команды сохраняют свои имена правил, поэтому новая опция не меняет
аудит уже знакомых форм.

Порядок решения не меняется: hard-ask → гард → allowlist → `ask` по
умолчанию, каждый шаг проходит по всем сегментам. `trusted_commands` не может
отменить hard-ask или гард: `["sudo ls"]`, `["git push origin"]` и даже
`["cat .env"]` остаются `ask` со своими правилами. Опция расширяет только
последний детерминированный шаг, который и так разрешает выполнение.

## Рассмотренные альтернативы

- **Добавить `npm test`, `node --test` в allowlist.** Встроенная таблица
  обещает read-only, а `npm test` запускает скрипт из `package.json`:
  сегодня тесты, завтра `curl | sh`. Разрешение, выданное всем проектам
  сразу, — это ложь в таблице и дыра по умолчанию.
- **Глобы в `trusted_commands` (`npm *`).** Одна звёздочка доверяет всей
  программе, включая `npm exec` и `npm publish`. Точные токены проверяемы
  глазами в диффе и не расширяются сами.
- **Разрешить один токен.** `["npm"]` или `["sh"]` — это доверие программе
  целиком. Минимум два токена заставляет назвать подкоманду.
- **Проверять только `;`.** Перевод строки, `&&`, `|` и `$()` делают то же
  самое; набор метасимволов берётся тот же, что у гарда.
- **Блок-лист опасных программ (`sh`, `python3`, `env`).** Список всегда
  неполный, а его наличие создаёт ложное чувство защиты. Вместо него —
  явная граница в документации: `["sh", "-c"]` оператор пишет сам и берёт
  риск на проект.
- **Отдельный `source: trust`.** Источник в аудите отвечает на вопрос «какой
  шаг решил», а не «кто написал правило». `allowlist` + `trust` не меняет
  словарь отчёта и не ломает разбор старых записей.

## Последствия

- `trusted_commands: ["npm test"]` разрешает `npm test` и `npm test 2>&1`
  (`rule: trust`), но не `npm run typecheck` и не `npm testing`.
- Префикс доверяет весь хвост команды. `["node --test"]` разрешает
  `node --test --test-reporter=./x.js`: репортер загружается как модуль, и его
  код исполняется. `["npm test"]` разрешает
  `npm test --script-shell=/tmp/evil`. Флаги после префикса не проверяются —
  иначе понадобилась бы вторая таблица, которая отстаёт от программ.
- `npm --prefix . test` не совпадает с `npm test`: глобальные флаги не
  пропускаются. Полную форму надо объявлять полной записью.
- `sudo`, `git push` и `cat .env` остаются `ask` при любом содержимом списка.
- Опция живёт в конфиге проекта. Глобальный конфиг её тоже принимает, но
  тогда разрешение действует везде — это решение оператора, не дефолт.
- Разбор происходит один раз при старте: в решателе лежат готовые массивы
  токенов, пер-вызовной токенизации нет.
- Аудит и отчёт не меняются: новые записи — обычные `allowlist`-кластеры с
  `rule: trust`.
