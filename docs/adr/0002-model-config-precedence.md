# Приоритет опции `model` над выбором в TUI

**Status**: accepted

Issue #5 требует порядка резолва эффективной модели «опции → оверрайд →
дефолт», а ADR-0001 называл выбор в TUI рантайм-оверрайдом, а конфиг —
дефолтом. Это разные вещи: по ADR-0001 пикер мог перебить `opencode.jsonc`,
по acceptance criteria — нет. Я выбираю вариант из #5: `options.model` —
старшая ступень, сохранённый выбор в TUI — средняя, `DEFAULT_MODEL`
(`opencode/jev-1.13-free`) — младшая.

Причина простая: `opencode.jsonc` — решение оператора, пикер — удобство.
Если конфиг пинит модель, выбор в TUI не должен молча его отменять,
иначе один и тот же репозиторий ведёт себя по-разному на машинах, где
кто-то когда-то потыкал `/classifier`. Headless-запуск и TUI при этом видят
одну и ту же эффективную модель.

Оверрайд всё равно сохраняется, даже когда конфиг его перекрывает. Если
опцию `model` убрать, вернётся последний выбор из TUI, а не дефолт. Тост
после сохранения в этом случае предупреждает, что конфиг пинит другую
модель, — иначе пользователь ищет баг там, где работает задуманное
поведение. Успешный `setModel` очищает in-memory кэш вердиктов, чтобы
следующая оценка шла новой моделью, а вычисление, начатое до смены, не
заполняло кэш старым результатом.

## Рассмотренные альтернативы

- **Оверрайд побеждает опцию.** Тогда `opencode.jsonc` перестаёт быть
  источником правды: пикер на одной машине меняет поведение, а конфиг
  приходится проверять вторым способом. Для headless- и CI-запусков это
  худший вариант — модель зависит от чужого клика.
- **Один источник: только конфиг, без пикера.** Противоречит user story 16:
  выбирать модель, не редактируя конфиг руками. Пикер оставлен, но
  подчинён конфигу.
- **Один источник: только `ctx.storage`, конфиг как начальное значение.**
  Тогда после первого выбора `opencode.jsonc` перестаёт что-либо решать,
  и обновление конфига в dotfiles не доезжает до пользователя.

## Последствия

- Порядок: `options.model` → `model_override` из `ctx.storage` →
  `opencode/jev-1.13-free`; `config` возвращает источник (`options`,
  `override`, `default`).
- `setModel` валидирует модель по каталогу и сохраняет её даже под
  перекрывающей опцией.
- TUI предупреждает тостом, когда эффективная модель не изменилась из-за
  конфига.
- Смена модели очищает кэш вердиктов; вычисление старой модели, начатое до
  смены, не может заполнить его повторно.
- `options.model` читается при старте серверной части: чтобы применить
  правку конфига, нужен рестарт. Выбор в TUI, который не перекрыт опцией,
  применяется со следующего вызова без рестарта.
